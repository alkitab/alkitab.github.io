Глава 01 · Основы

Знакомство с Debian и командной строкой

Debian GNU/Linux — один из старейших и наиболее уважаемых дистрибутивов Linux. Основанный в 1993 году Иэном Мёрдоком, Debian славится стабильностью, тщательным тестированием пакетов и полностью свободным программным обеспечением. На Debian построены десятки других дистрибутивов: Ubuntu, Linux Mint, Kali Linux, Raspbian для Raspberry Pi. Если вы работаете в Debian, ваши навыки переносятся на всю экосистему Debian-подобных систем.

Для разработки Bash-скриптов и работы с базами данных Debian подходит идеально. В стандартной поставке уже есть Bash, основные утилиты GNU (coreutils), текстовые редакторы (nano, vim), система пакетов apt. Установка дополнительных компонентов — SQLite, PostgreSQL, MariaDB, арабских шрифтов — выполняется одной командой и не требует сложной настройки.

Командная строка vs графический интерфейс

Графический интерфейс (GUI) удобен для повседневных задач: браузер, текстовый редактор, просмотр фотографий. Но для автоматизации, работы с серверами и разработкой скриптов командная строка (CLI) несравненно мощнее. Причин несколько. Во-первых, команды можно записывать в скрипт и повторять тысячи раз без ручного вмешательства. Во-вторых, команды легко комбинировать через конвейеры, получая сложную обработку данных из простых кирпичиков. В-третьих, командная строка работает по SSH на удалённых серверах без графической оболочки — а большинство серверов именно такие.

В Debian 12 (bookworm) по умолчанию устанавливается рабочий стол GNOME, но терминал всегда доступен через комбинацию Ctrl+Alt+T или поиск по приложению «Терминал». Если вы установили Debian без GUI (серверный вариант), вы окажетесь в чистом текстовом режиме — это нормально, всё, что описано в книге, работает и там.

Запуск терминала и первая команда

Откройте терминал. Вы увидите приглашение вида user@debian:~$. Это и есть командная строка Bash. Здесь user — имя пользователя, debian — имя хоста, ~ — текущая директория (домашняя), $ — приглашение обычного пользователя. Если стоите под root, будет # вместо $.

user@debian:~$ echo "Привет, Debian!"
Привет, Debian!
user@debian:~$ bash --version | head -1
GNU bash, версия 5.2.15(1)-release (x86_64-pc-linux-gnu)

Команда echo печатает свой аргумент на экран. Команда bash --version показывает версию Bash, а вертикальная черта | передаёт её вывод в head -1, которая оставляет только первую строку. Так выглядит конвейер — основная идиома Unix.

Права суперпользователя: su и sudo

Многие системные операции — установка пакетов, редактирование конфигурации в /etc, запуск служб — требуют прав root. В Debian есть два способа получить эти права. Первый — команда su (switch user): после ввода пароля root вы переключаетесь в его контекст. Второй — sudo, которая выполняет одну команду с правами root. По умолчанию в Debian sudo может быть не настроен для вашего пользователя.

user@debian:~$ su -
Пароль:
root@debian:~# apt update && apt upgrade -y
...
root@debian:~# exit
user@debian:~$

Чтобы включить sudo для своего пользователя, выполните от root: adduser user sudo, затем перезайдите в систему. После этого можно писать sudo apt install sqlite3 вместо su - + команда + exit. В этой книге мы будем использовать sudo — это общепринятый стиль.

Обновление системы

Перед началом работы обновим список пакетов и саму систему. Это рекомендуется делать после установки и регулярно thereafter. Команда apt update обновляет индексы пакетов из репозиториев, apt upgrade — устанавливает новые версии уже установленных пакетов.

Обновление системыbash
sudo apt update
sudo apt upgrade -y
sudo apt install -y bash-completion vim git curl

Пакет bash-completion добавляет автодополнение по клавише Tab для команд и опций — бесценная экономия времени. vim — мощный текстовый редактор (альтернатива nano для новичков). git и curl — инструменты разработчика, пригодятся позже.

Совет

Если команда sudo apt ругается на «Permission denied», значит ваш пользователь не в группе sudo. Выполните su -, введите пароль root, затем adduser ваш_логин sudo и перезайдите в систему.

Структура книги и约定

В этой книге команды, которые вы вводите в терминал, показаны в тёмных блоках с зелёным приглашением user@debian:~$. Содержимое скриптов — в светлых моноширинных блоках с подсветкой синтаксиса. Имена файлов и команд в тексте выделены как так. Важные замечания — в рамках с заглавием «Совет», «Предупреждение» или «Практика».

Все примеры рассчитаны на Debian 12 (bookworm), но будут работать и в Debian 11 (bullseye), и в Ubuntu 22.04+ / 24.04+, и в большинстве производных дистрибутивов. Если вы на другой системе (Arch, Fedora), имена пакетов и пути могут отличаться — уточняйте в документации вашего дистрибутива.

Глава 02 · Файлы

Базовые команды для работы с файлами

Файловая система Linux — это дерево с корнем в /. Все диски, флешки, сетевые ресурсы монтируются как подкаталоги этого дерева. В отличие от Windows, нет букв дисков (C:, D:) — всё единая иерархия. Понимание этой структуры необходимо для эффективной работы в Bash.

Ключевые каталоги

ПутьНазначение
/Корень файловой системы
/home/userДомашний каталог пользователя (сокращение ~)
/etcКонфигурационные файлы системы
/usrПрограммы пользователя, документация
/varПеременные данные: логи, базы данных, кэш
/tmpВременные файлы, очищаются при перезагрузке
/bin, /sbinСистемные утилиты (в Debian 12 это символические ссылки на /usr/bin, /usr/sbin)

Для нашего проекта словаря важны три каталога. ~/dict-ar-ru — рабочая папка проекта, где будут скрипты и БД. /etc — сюда иногда кладут общесистемные конфиги (но для личного словаря это не нужно). /usr/share/fonts — системные шрифты, включая арабские.

Навигация: pwd, cd, ls

Команда pwd (print working directory) показывает текущий каталог. cd (change directory) меняет текущий каталог. ls (list) показывает содержимое каталога.

user@debian:~$ pwd
/home/user
user@debian:~$ ls
Документы  Загрузки  Изображения  Музыка  Шаблоны
user@debian:~$ ls -la
drwxr-xr-x  2 user user 4096 окт 23 10:00 .
drwxr-xr-x  4 root root 4096 окт 20 09:00 ..
-rw-r--r--  1 user user  220 окт 15 12:00 .bashrc
drwx------  3 user user 4096 окт 23 09:30 .config

Флаг -l даёт «длинный» формат с правами, владельцем, размером и датой. Флаг -a показывает скрытые файлы (начинающиеся с точки). Строка drwxr-xr-x — это права доступа: d (каталог), затем три группы по три символа для владельца, группы и остальных.

Создание и удаление

Создание структуры проектаbash
# Создаём главный каталог проекта
mkdir ~/dict-ar-ru
mkdir ~/dict-ar-ru/{scripts,data,backup,docs}

# Переходим внутрь
cd ~/dict-ar-ru

# Создаём пустые файлы
touch scripts/dict.sh scripts/config.sh
touch data/words.csv data/schema.sql

# Проверяем
ls -R

Команда mkdir -p создаёт вложенные каталоги без ошибок, если они уже есть. Фигурные скобки {a,b,c} — это Bash-расширение: mkdir {scripts,data,backup} раскрывается в три отдельных аргумента. Очень удобно для создания нескольких однотипных каталогов.

Удаление: rmdir удаляет пустой каталог, rm — файлы, rm -r — каталоги рекурсивно (со всем содержимым), rm -rf — без подтверждения. Будьте осторожны с rm -rf: она не спрашивает подтверждения и не отправляет в корзину.

Предупреждение

Никогда не выполняйте rm -rf / или rm -rf ~/* — это удалит всю систему или все ваши файлы. Если нужно удалить конкретный каталог, всегда вводите полный путь и проверяйте его ls перед удалением.

Копирование и перемещение

Команды cp (copy) и mv (move) копируют и перемещают файлы и каталоги. cp -r копирует каталог рекурсивно. mv также используется для переименования: в Linux переименование — это перемещение файла в тот же каталог с новым именем.

Копирование и перемещениеbash
# Копируем скрипт-шаблон
cp scripts/dict.sh scripts/dict_backup.sh

# Переименовываем
mv data/words.csv data/words_initial.csv

# Копируем весь каталог scripts в backup
cp -r scripts backup/scripts_$(date +%Y%m%d)

Здесь $(date +%Y%m%d) — это командная подстановка: результат команды date вставляется в строку. Получится каталог вроде backup/scripts_20260123. Так удобно делать ежедневные резервные копии.

Просмотр содержимого файлов

Команда cat (concatenate) печатает содержимое файла целиком. less открывает постраничный просмотрщик с поиском (нажмите / для поиска, q для выхода). head -n 10 и tail -n 10 показывают первые и последние 10 строк. tail -f следит за файлом в реальном времени — незаменимо для просмотра логов.

user@debian:~/dict-ar-ru$ cat scripts/config.sh
#!/bin/bash
DB_PATH="$HOME/dict-ar-ru/data/dict.db"
user@debian:~/dict-ar-ru$ head -3 data/words.csv
arabic,russian,transcription
سلام,мир,salaam
كتاب,книга,kitab
user@debian:~/dict-ar-ru$ less README.md
(постраничный просмотр)

Права доступа: chmod и chown

Каждый файл в Linux имеет права для трёх категорий: владельца (user), группы (group) и остальных (others). Права — это комбинация чтения (r, 4), записи (w, 2) и исполнения (x, 1). Сумма даёт восьмеричное число: 7 = rwx, 6 = rw-, 5 = r-x, 4 = r--.

Команда chmod меняет права. Чтобы сделать скрипт исполняемым, достаточно chmod +x script.sh. Команда chown меняет владельца и группу (требует sudo).

Права доступаbash
# Делаем скрипт исполняемым
chmod +x scripts/dict.sh

# Эквивалентная запись в восьмеричной системе
chmod 755 scripts/dict.sh   # rwxr-xr-x

# Только владелец может читать и писать, остальные — ничего
chmod 600 data/dict.db

# Сменить владельца (требует sudo)
sudo chown user:user /var/lib/dict-ar-ru/dict.db

Для Bash-скриптов стандартные права — 755: владелец может всё, остальные читать и выполнять, но не изменять. Для файлов с чувствительными данными (пароли, БД) — 600: только владелец читает и пишет.

Глава 03 · Переменные

Переменные, строки и параметры

Переменная в Bash — это именованная ячейка памяти, хранящая строку (или, в особых случаях, число). Имя переменной может содержать буквы, цифры и знак подчёркивания, но не должно начинаться с цифры. По соглашению имена обычных переменных пишут в нижнем регистре (db_path), а системных и констант — в верхнем (PATH, DB_NAME).

Объявление и чтение

Переменная объявляется знаком равенства без пробелов вокруг: name="value". Для чтения используется знак доллара: $name или ${name}. Вторая форма безопаснее — она явно отделяет имя переменной от последующего текста.

Объявление переменныхbash
#!/bin/bash

WORD_AR="كتاب"
WORD_RU="книга"
DB_PATH="$HOME/dict-ar-ru/data/dict.db"

echo "Арабское: $WORD_AR"
echo "Русское: ${WORD_RU}"
echo "БД: $DB_PATH"

Пробелы вокруг = недопустимы. Запись WORD_AR = "книга" будет воспринята как команда WORD_AR с аргументами = и "книга" — и приведёт к ошибке «command not found». Это одна из самых частых ошибок новичков.

Специальные переменные

Bash имеет набор предопределённых переменных, доступных в любом скрипте. Они дают доступ к аргументам командной строки, кодам возврата, идентификатору процесса и другим системным данным.

ПеременнаяЗначение
$0Имя скрипта (как он был вызван)
$1, $2, ..., $9Первый, второй, ..., девятый аргумент
${10}, ${11}Аргументы с 10-го (нужны фигурные скобки)
$#Количество аргументов
$@Все аргументы как отдельные строки
$*Все аргументы как одна строка
$?Код возврата последней команды (0 = успех)
$$PID текущего процесса (для временных файлов)
$!PID последнего фонового процесса
$HOME, $USER, $PWDДомашний каталог, имя пользователя, текущая директория

Различие между $@ и $* тонкое. Без кавычек они ведут себя одинаково. С кавычками: "$@" раскрывается в отдельные строки (по одной на аргумент), а "$*" — в одну строку, разделённую пробелом (или первым символом IFS). Почти всегда нужен "$@".

Кавычки: одинарные, двойные, backticks

Bash различает три вида кавычек, и их поведение важно понимать.

Одинарные кавычки 'text' — буквальная строка. Никакие подстановки не выполняются: '$HOME' напечатает буквально $HOME, а не путь к домашнему каталогу. Используются для строк с символами $, которые нужно передать как есть.

Двойные кавычки "text" — подстановка разрешена. "$HOME" раскроется в /home/user. Это стандартный способ писать строки с переменными.

Backticks `cmd` — устаревший синтаксис командной подстановки. Современный аналог — $(cmd), который предпочтительнее: легко вкладывается, читается лучше. Не используйте backticks в новых скриптах.

Кавычки и подстановкаbash
name="Анна"

echo 'Привет, $name'        # Привет, $name
echo "Привет, $name"        # Привет, Анна
echo "Сегодня: $(date +%d.%m.%Y)"
echo "Дом: $HOME"             # Дом: /home/user
echo 'Символ $ без подстановки'
Совет

Всегда заключайте переменные в двойные кавычки, когда используете их в командах: "$var", а не $var. Это защитит от проблем с пробелами в значениях (например, путями с пробелами) и пустыми переменными.

Командная подстановка

Синтаксис $(command) выполняет команду и подставляет её вывод в строку. Это позволяет динамически вычислять значения переменных. Например, получить текущую дату, количество строк в файле, имя хоста.

Командная подстановкаbash
TODAY=$(date +%Y-%m-%d)
WORD_COUNT=$(wc -l < data/words.csv)
HOST=$(hostname)
FIRST_ARABIC=$(head -1 data/words.csv | cut -d, -f1)

echo "Дата: $TODAY"
echo "Записей в словаре: $WORD_COUNT"
echo "Хост: $HOST"

Арифметика: $(( ))

Bash не умеет напрямую работать с числами как типом — переменные всегда строки. Но конструкция $((expression)) выполняет целочисленные арифметику. Поддерживаются + - * / % (остаток), ** (степень), скобки для приоритета, инкремент ++ и декремент --.

Арифметикаbash
a=10
b=3

echo "$a + $b = $((a + b))"     # 13
echo "$a / $b = $((a / b))"     # 3 (целочисленное деление)
echo "$a % $b = $((a % b))"     # 1 (остаток)
echo "$a ** $b = $((a ** b))"   # 1000

# Инкремент
((a++))
echo "a теперь: $a"            # 11

Для дробной арифметики Bash не подходит — используйте bc или awk. Например, echo "scale=2; 10/3" | bc даст 3.33.

Чтение ввода: read

Команда read читает строку из стандартного ввода (или из файла через перенаправление) и записывает в переменные. С флагом -p выводит приглашение, с -s — скрывает ввод (для паролей), с -r — не интерпретирует обратные слэши (рекомендуется всегда).

Чтение ввода пользователяbash
#!/bin/bash
# Скрипт add_word.sh — добавляет слово в словарь

read -rp "Введите арабское слово: " arabic
read -rp "Введите русский перевод: " russian
read -rp "Транскрипция (латиницей): " transcription

echo "$arabic,$russian,$transcription" >> data/words.csv
echo "Добавлено: $arabic → $russian"

Здесь -r предохраняет от проблем с обратными слэшами (например, в Windows-путях), -p задаёт приглашение. >> дописывает в конец файла, не перезаписывая его.

Длина строки и срезы

Bash умеет работать со строками без вызова внешних команд. ${#var} даёт длину строки, ${var:offset:length} — подстроку, ${var#pattern} и ${var%pattern} удаляют совпадение с начала и с конца.

Строковые операцииbash
word=" dictionary "

echo "${#word}"             # 12 (длина с пробелами)
echo "${word:1:10}"         # dictionary (срез)
echo "${word#d}"            # ictionary (удалить d в начале)
echo "${word%d}"            # ictionary (удалить d в конце)

# Замена подстроки
echo "${word/o/0}"          # dicti0nary (первое вхождение)
echo "${word//o/0}"         # dicti0nary (все вхождения)

# Удаление пробелов в начале и конце
echo "${word## }"           # "dictionary " (только в начале)
echo "${word%% }"           # " dictionary" (только в конце)

Эти операции работают быстро и не порождают новых процессов. Для простых преобразований строк всегда предпочитайте их внешним утилитам.

Экспорт переменных: export

Обычная переменная видна только в текущем скрипте. Команда export делает её доступной дочерним процессам (командам, запущенным из этого скрипта). Это важно для конфигурации: например, переменная DATABASE_URL должна быть экспортирована, чтобы её видела программа-клиент БД.

Экспорт переменныхbash
#!/bin/bash
# config.sh — общие настройки

export DB_PATH="$HOME/dict-ar-ru/data/dict.db"
export DICT_LANG_FROM="ar"
export DICT_LANG_TO="ru"
export PAGER="less"

# В другом скрипте
source config.sh   # загрузить переменные
echo "БД: $DB_PATH"

Команда source (или её синоним .) выполняет скрипт в текущей оболочке, не порождая новой. Так можно вынести общие настройки в отдельный файл и подключать его в разных скриптах.

Глава 04 · Ввод-вывод

Ввод-вывод и перенаправления

В Unix каждая программа имеет три стандартных потока: стандартный ввод (stdin, файловый дескриптор 0), стандартный вывод (stdout, дескриптор 1) и стандартный вывод ошибок (stderr, дескриптор 2). По умолчанию stdin подключён к клавиатуре, stdout и stderr — к экрану. Перенаправления позволяют изменить это поведение: взять ввод из файла, отправить вывод в файл или передать его другой команде.

Перенаправление вывода

Знак > перенаправляет stdout в файл, перезаписывая его. Знак >> дописывает в конец. Знак < берёт stdin из файла. Эти три операции — основа пакетной обработки данных в Bash.

Перенаправленияbash
# Перезаписать файл
echo "Словарь v1.0" > docs/README.md

# Дописать
echo "Дата создания: $(date)" >> docs/README.md
echo "" >> docs/README.md
echo "## Структура" >> docs/README.md

# Взять ввод из файла
wc -l < data/words.csv
# Эквивалент: cat data/words.csv | wc -l

Разделение stdout и stderr

Часто нужно отделить нормальный вывод от сообщений об ошибках. Синтаксис 2> перенаправляет только stderr, 2>&1 — объединяет stderr с stdout. Так можно записать ошибки в отдельный лог или проигнорировать их.

Разделение потоковbash
# Только stdout в файл, ошибки на экран
sqlite3 dict.db "SELECT * FROM words" > data/dump.txt

# Только stderr в файл
sqlite3 dict.db "SELECT * FROM words" 2> logs/error.log

# Объединить stdout и stderr в один файл
sqlite3 dict.db ".schema" > logs/schema.log 2>&1

# Игнорировать ошибки (отправить в /dev/null)
rm -f /tmp/nonexistent 2>/dev/null

Порядок перенаправлений важен: >file 2>&1 сначала открывает file для stdout, затем дублирует stderr в текущий stdout (то есть в файл). Обратный порядок 2>&1 >file даст другой результат: stderr пойдёт на экран, а stdout — в файл.

Конвейер (pipe)

Вертикальная черта | — конвейер — передаёт stdout одной команды на stdin другой. Это одна из самых мощных идей Unix: маленькие утилиты комбинируются в сложные pipeline. Конвейер создаёт неявный канал между процессами: данные проходят напрямую, без промежуточных файлов.

user@debian:~/dict-ar-ru$ cat data/words.csv | head -5 | tail -3
كتاب,книга,kitab
باب,дверь,bab
ماء,вода,maa

user@debian:~/dict-ar-ru$ cat data/words.csv | grep "كتاب"
كتاب,книга,kitab

user@debian:~/dict-ar-ru$ cat data/words.csv | cut -d, -f2 | sort | uniq -c | sort -rn | head
      3 книга
      2 дверь
      1 вода

Последний конвейер показывает типичный анализ данных: берём второй столбец (русские слова), сортируем, считаем дубликаты, сортируем по убыванию, оставляем топ-10. Каждая команда простая, вместе они дают мощный аналитический инструмент.

tee: T-образный разветвитель

Команда tee читает stdin и пишет его одновременно в файл и в stdout. Это позволяет «подсмотреть» за данными в середине конвейера, не разрывая его. Полезно для логирования.

tee — логирование конвейераbash
# Сохранить вывод в файл И показать на экране
sqlite3 dict.db "SELECT * FROM words" | tee data/dump.txt | head -10

# С флагом -a — дописывать, а не перезаписывать
echo "Запуск скрипта: $(date)" | tee -a logs/script.log

# Сохранить и stdout, и stderr в один лог, но видеть только stdout
some_command 2>&1 | tee logs/all.log | grep -v "^[Ee]rror"

xargs: из stdin в аргументы

Конвейер передаёт данные через stdin, но некоторые команды ожидают аргументы, а не stdin. Например, rm хочет имена файлов как аргументы. xargs берёт строки из stdin и превращает их в аргументы для указанной команды.

xargsbash
# Найти все .bak файлы и удалить
find . -name "*.bak" | xargs rm

# Безопаснее: имена с пробелами и спецсимволами
find . -name "*.bak" -print0 | xargs -0 rm

# Запустить sqlite3 с SQL из файла
echo "schema.sql" | xargs -I{} sqlite3 dict.db < {}

# Пакетная обработка: для каждого слова в файле
cat arabic_words.txt | xargs -I{} ./translate.sh {}

Флаг -0 в связке с find -print0 — стандартный способ безопасно передавать имена файлов с пробелами, кавычками и переводами строк. Всегда используйте эту пару для надёжных скриптов.

Here-doc и here-string

Here-doc (встроенный документ) позволяет передать многострочный текст в команду без создания файла. Синтаксис: command <<DELIMITER ... DELIMITER. Строки между ограничителями становятся stdin команды. Здесь DELIMITER — произвольное слово, обычно EOF или SQL.

Here-doc для SQLbash
#!/bin/bash
# apply_schema.sh — применить схему к SQLite

sqlite3 "$DB_PATH" <<SQL
CREATE TABLE IF NOT EXISTS words (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    arabic TEXT NOT NULL,
    russian TEXT NOT NULL,
    transcription TEXT,
    created_at TEXT DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_arabic ON words(arabic);
CREATE INDEX IF NOT EXISTS idx_russian ON words(russian);
SQL

echo "Схема применена"

Если ограничитель написать без кавычек (<<SQL), внутри here-doc работают подстановки переменных. Если в кавычках (<<'SQL') — текст передаётся буквально, без подстановок. Для SQL с переменными Bash используйте первый вариант, для SQL с символом $ — второй.

Here-string — это «одноразовый» here-doc для одной строки: command <<<"text". Удобно для коротких данных.

Here-stringbash
# Передать одну строку в bc для вычисления
bc <<< "2 + 2"

# Поиск в строке
grep "книга" <<< "это книга про bash"

# JSON в Python
python3 -c "import sys, json; print(json.loads(sys.stdin.read()))" <<< '{"a": 1}'

Глава 05 · Условия

Условия и ветвление

Условные операторы позволяют скрипту принимать решения в зависимости от данных. В Bash есть два основных способа: if-elif-else-fi для сложных проверок и case-esac для выбора из нескольких альтернатив. Оба опираются на код возврата команды: 0 означает успех (истина), ненулевое значение — ошибку (ложь).

Команда test и [[ ]]

Команда test (или её синоним [ ]) проверяет условия и возвращает 0 или 1. Современный Bash предлагает улучшенный синтаксис [[ ]], который поддерживает регулярные выражения, более безопасные операции со строками и не требует кавычек вокруг переменных в большинстве случаев.

ПроверкаИстинна, если
-z "$str"Строка пустая
-n "$str"Строка непустая
"$a" = "$b"Строки равны
"$a" != "$b"Строки не равны
"$a" < "$b"$a лексикографически раньше $b (в [[ ]])
-eq, -ne, -lt, -le, -gt, -geЧисловые сравнения: равно, не равно, меньше, меньше или равно, больше, больше или равно
-e "$f"Файл существует
-f "$f"Обычный файл
-d "$d"Каталог
-r "$f", -w "$f", -x "$f"Файл доступен для чтения / записи / исполнения
-s "$f"Файл существует и непустой

Синтаксис if

if-elif-elsebash
#!/bin/bash
# check_args.sh — проверка аргументов

if [[ $# -eq 0 ]]; then
    echo "Использование: $0 <arabic> <russian>"
    echo "Пример: $0 كتاب книга"
    exit 1
elif [[ $# -eq 1 ]]; then
    echo "Ошибка: не указан русский перевод"
    exit 1
else
    echo "Добавляем: $1 → $2"
fi

Ключевое слово then можно писать на той же строке после ; или на следующей. fi (if наоборот) закрывает блок. Аналогично работают case ... esac, for ... done, while ... done.

Логические операторы

Bash предлагает несколько способов комбинировать условия. Внутри [[ ]] работают && (И), || (ИЛИ), ! (НЕ). Между командами && и || работают как «выполни следующее, если предыдущая успешна/неуспешна».

Логические операторыbash
# Внутри [[ ]]
if [[ -n "$word" && "$word" != "quit" ]]; then
    echo "Слово: $word"
fi

# Между командами
[[ -f data/dict.db ]] && echo "БД существует"
[[ -f data/dict.db ]] || echo "БД не найдена"

# Эквивалентно if-then
[[ -f data/dict.db ]] && {
    echo "БД найдена"
    sqlite3 data/dict.db ".tables"
}

case: выбор по шаблону

Когда нужно сравнить значение с несколькими вариантами, case удобнее цепочки if-elif. Шаблоны поддерживают glob-символы: * (любая строка), ? (один символ), [abc] (один из перечисленных), | (или).

case для подкомандbash
#!/bin/bash
# dict.sh — главная команда словаря

ACTION="$1"
shift

case "$ACTION" in
    add)
        echo "Добавление слова: $@"
        ./add_word.sh "$@"
        ;;
    search)
        echo "Поиск: $1"
        ./search_word.sh "$1"
        ;;
    list|ls)
        echo "Все слова:"
        ./list_words.sh
        ;;
    stat*)
        echo "Статистика"
        ./stats.sh
        ;;
    help|--help|-h)
        echo "Использование: dict.sh {add|search|list|stats|help}"
        ;;
    *)
        echo "Неизвестная команда: $ACTION"
        echo "Введите 'dict.sh help' для справки"
        exit 1
        ;;
esac

Здесь shift убирает первый аргумент ($1), сдвигая все остальные влево: $2 становится $1 и так далее. После shift мы получаем «чистые» аргументы подкоманды в $@.

Шаблон list|ls) срабатывает на оба варианта. stat*) — на любое слово, начинающееся с stat (stats, statistics). *) в конце — это ветка по умолчанию, срабатывает, если ни один шаблон не подошёл.

Проверка существования файлов

Один из самых частых сценариев — проверить, существует ли файл, и только потом с ним работать. Это делает скрипты устойчивыми.

Защита от отсутствующих файловbash
DB="data/dict.db"

if [[ ! -f "$DB" ]]; then
    echo "БД не найдена, создаю новую..."
    sqlite3 "$DB" <<SQL
CREATE TABLE words (id INTEGER PRIMARY KEY, arabic TEXT, russian TEXT);
SQL
fi

# То же в одну строку
[[ -f "$DB" ]] || { echo "Создаю $DB"; touch "$DB"; }

Сравнение строк с учётом локали

Сравнение строк зависит от текущей локали. Для русского и арабского языков важно установить правильную локаль через LC_COLLATE, иначе порядок сортировки будет некорректным.

Локаль и сравнениеbash
# Проверить текущую локаль

# Установить UTF-8 локаль (если не установлена)
sudo dpkg-reconfigure locales
# Выбрать ru_RU.UTF-8 и en_US.UTF-8

# В скрипте принудительно
export LC_ALL=ru_RU.UTF-8
export LANG=ru_RU.UTF-8

# Сравнение кириллических строк
if [[ "книга" < "ручка" ]]; then
    echo "книга идёт раньше"
fi

Глава 06 · Циклы

Циклы

Циклы позволяют выполнять блок кода многократно. В Bash есть три основных вида циклов: for для перебора списка, while для повторения, пока условие истинно, и until — пока ложно. Все они закрываются ключевым словом done.

Цикл for

Цикл for перебирает элементы списка. Список может быть задан явно, результатом раскрытия шаблона (glob), или выводом команды в $().

for — разные виды списковbash
# Явный список
for word in книга ручка стол окно; do
    echo "Слово: $word"
done

# Перебор файлов по шаблону
for f in data/*.csv; do
    echo "Файл: $f ($(wc -l < "$f") строк)"
done

# Перебор аргументов скрипта
for arg in "$@"; do
    echo "Аргумент: $arg"
done

# Перебор вывода команды
for user in $(cut -d: -f1 /etc/passwd); do
    echo "Пользователь: $user"
done

# C-style: числовой диапазон
for ((i=1; i<=10; i++)); do
    echo "Число: $i"
done

Цикл в C-стиле for ((init; cond; step)) удобен, когда нужен числовой счётчик. Двойные скобки обязательны. Диапазоны можно задавать и так: for i in {1..10} или for i in {1..10..2} (с шагом 2).

Цикл while

while выполняет блок, пока команда (или условие [[ ]]) возвращает 0. Это классический способ построчного чтения файла.

while — построчное чтениеbash
# Читать файл построчно
while IFS= read -r line; do
    echo "Строка: $line"
done < data/words.csv

# Читать CSV, разбивая по запятой
while IFS=, read -r arabic russian transcription; do
    echo "$arabic → $russian ($transcription)"
done < <(tail -n +2 data/words.csv)

# Бесконечный цикл с выходом по условию
while true; do
    read -rp "Введите слово (или 'quit'): " word
    [[ "$word" == "quit" ]] && break
    echo "Вы ввели: $word"
done

Конструкция IFS=, read -r a b c читает строку, разделяя её по запятой на три переменные. IFS= (пустой) перед read без аргумента сохраняет начальные и конечные пробелы. Подстановка процесса <(<cmd>) передаёт вывод команды как файл — это лучше, чем конвейер, потому что переменные из while остаются видимыми после цикла.

break и continue

break выходит из цикла досрочно, continue переходит к следующей итерации. С числовым аргументом: break 2 выходит из двух уровней вложенности.

break и continuebash
# Пропустить пустые строки, выйти на слове "stop"
while IFS= read -r line; do
    [[ -z "$line" ]] && continue   # пустая строка
    [[ "$line" == "stop" ]] && break
    echo "$line"
done < input.txt

# continue с числом — перейти к следующей итерации внешнего цикла
for i in {1..5}; do
    for j in {1..5}; do
        (( (i*j) % 2 == 0 )) && continue 2
        echo -n "$i*$j=$((i*j)) "
    done
    echo
done

Цикл until

until — это while с обратным условием: выполняется, пока условие ложно. Используется реже, но иногда семантически правильнее.

until — ждать появления файлаbash
# Ждать, пока файл не появится (с таймаутом)
tries=0
until [[ -f /tmp/ready.txt ]] || (( tries >= 60 )); do
    sleep 1
    ((tries++))
done

[[ -f /tmp/ready.txt ]] && echo "Файл появился" || echo "Таймаут"

select: интерактивное меню

Команда select создаёт интерактивное меню: печатает пронумерованный список, ждёт ввода пользователя, помещает выбранный элемент в переменную. Удобно для простых CLI-приложений.

select — менюbash
#!/bin/bash
# menu.sh — меню словаря

PS3="Выберите действие: "
select action in "Добавить слово" "Найти слово" "Показать все" "Выход"; do
    case "$action" in
        "Добавить слово")   ./add_word.sh ;;
        "Найти слово")     read -rp "Слово: " w; ./search_word.sh "$w" ;;
        "Показать все")     ./list_words.sh ;;
        "Выход")           break ;;
        *)                echo "Неверный выбор" ;;
    esac
done

Глава 07 · Функции

Функции

Функции в Bash — это именованные блоки кода, которые можно вызывать многократно. Они принимают позиционные параметры ($1, $2 внутри функции — это аргументы функции, а не скрипта), возвращают код завершения через return и могут использовать локальные переменные через local. Функции — основной способ структурирования больших скриптов.

Объявление и вызов

Есть два синтаксиса объявления функции. function name() { ... } и name() { ... } — эквивалентны, второй короче и портативнее. Функция должна быть объявлена до её вызова — Bash читает скрипт сверху вниз.

Объявление функцииbash
#!/bin/bash

# Объявление
greet() {
    echo "Привет, $1!"
}

# Альтернативный синтаксис с ключевым словом function
function add_word() {
    echo "$1,$2,$3" >> data/words.csv
}

# Вызов
greet "Мир"                # Привет, Мир!
add_word "كتاب" "книга" "kitab"

Параметры и return

Внутри функции $1..$N — это аргументы функции, $0 — имя функции (в Bash 4+), $# — количество аргументов функции, $@ — все аргументы функции. Переменные $?, $$, $! относятся к процессу в целом.

Команда return выходит из функции с указанным кодом возврата (0-255). Без аргумента возвращает код последней команды. Код возврата проверяется через $? сразу после вызова. return не возвращает значение — для этого используют подстановку команды.

Параметры и returnbash
check_word() {
    if [[ -z "$1" ]]; then
        echo "Ошибка: пустое слово" >&2
        return 1
    fi
    return 0
}

# Вызов и проверка кода
if check_word "книга"; then
    echo "Слово валидно"
else
    echo "Отклонено"
fi

Возврат значения через подстановку

Чтобы функция вернула строку, её выводят через echo и захватывают в вызывающем коде через $(). Это идиоматичный способ возврата значений в Bash.

Возврат значенияbash
normalize_arabic() {
    # Удалить огласовки и нормализовать алифы
    echo "$1" | sed 's/[\x{064B}-\x{0652}]//g; s/آ/ا/g; s/أ/ا/g; s/إ/ا/g'
}

format_entry() {
    local ar="$1"
    local ru="$2"
    local tr="$3"
    echo "$ar | $ru | $tr"
}

# Использование
clean=$(normalize_arabic "كِتَابٌ")
echo "Нормализованное: $clean"      # كتاب

entry=$(format_entry "سلام" "мир" "salaam")
echo "$entry"                         # سلام | мир | salaam

Локальные переменные: local

Без local переменные внутри функции изменяют глобальные. Это частый источник багов. local создаёт переменную, видимую только внутри функции и её дочерних функций.

local — изоляция переменныхbash
counter=0   # глобальная

increment() {
    local step="${1:-1}"   # локальная, по умолчанию 1
    ((counter += step))
    echo "Шаг: $step, счётчик: $counter"
}

increment 5      # Шаг: 5, счётчик: 5
increment 3      # Шаг: 3, счётчик: 8
echo "$step"          # (пусто) — step не видна снаружи
echo "$counter"        # 8

Конструкция ${1:-1} — это значение первого аргумента, или 1, если аргумент пустой. Это стандартный приём для задания значений по умолчанию.

Рекурсия

Bash поддерживает рекурсию — функция может вызывать сама себя. Это удобно для задач вроде обхода дерева каталогов, факториала, вычисления Фибоначчи. Но помните о лимите вложенности (обычно около 1000 уровней).

Рекурсия — факториалbash
factorial() {
    local n="$1"
    if (( n <= 1 )); then
        echo 1
    else
        local sub=$(factorial $((n - 1)))
        echo $((n * sub))
    fi
}

echo "5! = $(factorial 5)"   # 120
echo "10! = $(factorial 10)"  # 3628800

Функции можно вынести в отдельный файл и подключать через source. Это позволяет переиспользовать код в нескольких скриптах.

Глава 08 · Текстовые утилиты

Текстовые утилиты: grep, sed, awk

Три классические утилиты Unix — grep, sed и awk — образуют мощный инструментарий для обработки текста. grep ищет по шаблону, sed редактирует поток, awk выполняет программы над структурированным текстом. Владение этими утилитами позволяет решать задачи обработки словаря в одну-две команды вместо десятков строк на Bash.

grep: поиск по шаблону

grep (Global Regular Expression Print) печатает строки, содержащие совпадение с регулярным выражением. Это самый частый инструмент поиска в Unix.

ФлагНазначение
-iИгнорировать регистр
-vИнвертировать: печатать строки БЕЗ совпадения
-nПечатать номер строки
-cТолько количество совпадающих строк
-rРекурсивно по каталогу
-lТолько имена файлов с совпадениями
-EРасширенные регулярные выражения (как egrep)

grep — поиск в словареbash
# Найти все строки со словом "книга"
grep "книга" data/words.csv

# Без учёта регистра, с номерами строк

sed: потоковый редактор

sed (Stream Editor) применяет команды редактирования к каждой строке входного потока. Самая частая команда — s/old/new/g: заменить old на new глобально.

sed — заменыbash
# Заменить все запятые на табуляции (CSV → TSV)
sed 's/,/\t/g' data/words.csv

# Заменить только первое вхождение в строке
sed 's/,/|/' data/words.csv

# Удалить строки, содержащие "TODO"
sed '/TODO/d' notes.txt

# Удалить пустые строки
sed '/^$/d' data/words.csv

# Печатать только строки с 5 по 10
sed -n '5,10p' data/words.csv

# Удалить огласовки из арабского текста
sed 's/[\x{064B}-\x{0652}]//g' input.txt

# Редактировать файл на месте (с бэкапом .bak)
sed -i.bak 's/old/new/g' file.txt

Флаг -i редактирует файл на месте (без вывода в stdout). С суффиксом -i.bak создаёт резервную копию. Без суффикса -i — без бэкапа. Будьте осторожны: всегда сначала проверяйте команду без -i, потом добавляйте его.

Флаг -E включает расширенные регулярные выражения (как grep -E). В них +, ?, {n,m}, |, () работают без обратного слэша.

awk: язык обработки структурированного текста

awk — это полноценный язык программирования, оптимизированный для обработки табличных данных. Он читает файл построчно, разбивает на поля по разделителю (по умолчанию пробел), и применяет программу вида условие { действие }.

awk — основыbash
# Печатать первую колонку каждого файла CSV
awk -F, '{print $1}' data/words.csv

# Печатать вторую колонку только для строк с "книга"
awk -F, '/книга/ {print $2}' data/words.csv

# Пропустить заголовок, посчитать строки
awk -F, 'NR>1 {count++} END {print count}' data/words.csv

# Поменять колонки местами
awk -F, '{print $2","$1","$3}' data/words.csv > data/reversed.csv

# Условие по длине слова в первой колонке
awk -F, 'length($1) > 4 {print $0}' data/words.csv

# Сумма длин русских слов (колонка 2)
awk -F, 'NR>1 {sum += length($2)} END {print "Средняя длина:", sum/(NR-1)}' data/words.csv

Встроенные переменные awk: NR (номер строки), NF (количество полей), $0 (вся строка), $1..$N (поля), FS (разделитель полей), OFS (разделитель в выводе). Блок BEGIN выполняется до чтения, END — после.

awk — отчётыbash
# Простой отчёт по словарю
awk -F, '
BEGIN {
    print "=== Отчёт по словарю ==="
    print "Слово\t\tПеревод\t\tТранскрипция"
    print "-----\t\t-------\t\t------------"
}
NR>1 {
    printf "%-15s\t%-15s\t%s\n", $1, $2, $3
    count++
}
END {
    print "-----"
    print "Всего записей:", count
}
' data/words.csv

Глава 09 · Regex

Регулярные выражения

Регулярные выражения (regex) — это компактный язык для описания шаблонов в тексте. Они применяются в grep, sed, awk, bash [[ ]]=~ и большинстве языков программирования. В контексте словаря regex позволяет валидировать арабские и русские слова, искать по морфемам, нормализовать написание.

Базовый синтаксис

СимволЗначение
.Любой символ (кроме перевода строки)
^Начало строки
$Конец строки
*0 или более повторений предыдущего
+1 или более (только в ERE)
?0 или 1 (только в ERE)
{n}, {n,m}n повторений / от n до m
[abc]Любой из перечисленных
[^abc]Любой, кроме перечисленных
[a-z]Диапазон (только ASCII)
(abc|def)Группа с альтернативой (ERE)

В Bash есть три диалекта регулярных выражений: BRE (Basic, по умолчанию в grep и sed), ERE (Extended, флаг -E), PCRE (Perl, флаг -P в GNU grep). Для большинства задач достаточно ERE — его и будем использовать.

Классы POSIX

Поскольку [a-z] работает только для ASCII, для Unicode (русский, арабский) используют классы POSIX или диапазоны Unicode.

[[:alnum:]]Буквы и цифры

[[:upper:]], [[:lower:]]Верхний/нижний регистр

Валидация арабских и русских слов

Арабский алфавит в Unicode занимает диапазон U+0600 — U+06FF (Basic Arabic) и U+0750 — U+077F (Arabic Supplement). Кириллица — U+0400 — U+04FF.

Валидация словbash
#!/bin/bash
# validate_word.sh — проверка слова

validate_arabic() {
    local word="$1"
    # Только арабские буквы (диапазон 0600-06FF), без огласовок
    if [[ "$word" =~ ^[\u0600-\u06FF]+$ ]]; then
        return 0
    else
        return 1
    fi
}

validate_russian() {
    local word="$1"
    # Кириллица + дефис (для сложных слов)
    if [[ "$word" =~ ^[а-яА-ЯёЁ-]+$ ]]; then
        return 0
    else
        return 1
    fi
}

# Использование
if validate_arabic "كتاب"; then echo "OK"; fi
if validate_russian "привет"; then echo "OK"; fi
if ! validate_russian "hello"; then echo "Не русское"; fi

Bash [[ ]]=~ и захват групп

Оператор =~ внутри [[ ]] проверяет совпадение с расширенным регулярным выражением. Захваченные группы доступны в массиве ${BASH_REMATCH[@]}.

BASH_REMATCHbash
parse_entry() {
    local line="$1"
    if [[ "$line" =~ ^([^,]+),([^,]+),([^,]+)$ ]]; then
        echo "Арабское: ${BASH_REMATCH[1]}"
        echo "Русское:  ${BASH_REMATCH[2]}"
        echo "Транскр.: ${BASH_REMATCH[3]}"
    else
        echo "Неверный формат" >&2
        return 1
    fi
}

parse_entry "كتاب,книга,kitab"
Совет

Никогда не заключайте regex в кавычки внутри [[ ]]=~ — Bash раскроет их как строку, а не как regex. Используйте переменную: re='^[a-z]+$'; [[ "$s" =~ $re ]]. Это позволяет менять regex динамически и избегает проблем с экранированием.

Команда fc-list (от fontconfig) показывает все установленные шрифты. Фильтр grep -i arabic оставляет только те, что поддерживают арабский. Если список пустой, шрифты не установились или не подхватились — выполните fc-cache -fv для пересборки кэша.

Настройка раскладки клавиатуры

Для ввода арабского текста нужна вторая раскладка. В Debian раскладки настраиваются в файле /etc/default/keyboard или через графический интерфейс GNOME.

/etc/default/keyboardconfig
# /etc/default/keyboard
XKBMODEL="pc105"
XKBLAYOUT="us,ru,ar"          # английская, русская, арабская
XKBVARIANT=",,"                 # варианты (пусто = default)

# grp:alt_shift_toggle — переключение по Alt+Shift
# grp_led:scroll — индикация лампочкой ScrollLock

После изменения файла примените настройки: sudo setupcon (для текстовой консоли) или перезайдите в X-сессию. В GNOME те же настройки доступны через «Настройки → Клавиатура + Регион и язык».

Временно переключить раскладку из терминала (для X-сессии):

user@debian:~$ setxkbmap us,ru,ar -option grp:alt_shift_toggle  # вернуть

Ввод арабского в терминале

Современные эмуляторы терминала (GNOME Terminal, Konsole, Terminator, XFCE4-Terminal) поддерживают ввод и отображение RTL-текста. Однако Bidirectional (двунаправленный) алгоритм в чистом терминале работает не идеально: арабские буквы могут отображаться в логическом порядке слева направо, без соединения. Для критичных задач используйте текстовый редактор (vim, nano, gedit) вместо cat/echo.

user@debian:~$ echo "كتاب — это книга"
كتاب — это книга

user@debian:~$ read -p "Введите арабское: " ar; echo "Вы ввели: $ar"
Введите арабское: سلام
Вы ввели: سلام

Если вместо арабского вы видите прямоугольники или знаки вопроса, проблема в шрифте терминала. В GNOME Terminal: «Правка → Параметры → Профили → Текст → Моноширинный шрифт» — выберите шрифт с поддержкой арабского, например DejaVu Sans Mono или Noto Sans Mono CJK. Для терминала xterm используйте xterm -fa 'Noto Sans Mono' -en UTF-8.

Корректный рендеринг RTL через fribidi

Утилита fribidi (Free Implementation of the Unicode Bidirectional Algorithm) переупорядочивает арабский текст для отображения в терминалах, не поддерживающих Unicode Bidi. Установите: sudo apt install fribidi.

user@debian:~$ echo "مرحبا بالعالم" | fribidi
مرحبا بالعالم

user@debian:~$ printf "Арабское: %s\n" "$(echo 'كتاب' | fribidi)"
Арабское: كتاب

Для полностью корректного рендеринга с соединением букв и огласовками нужен сложный текстовый движок (Pango, HarfBuzz). В терминале GNOME/Konose это уже сделано, но в скриптах для piped-вывода может потребоваться fribidi.

Сравнение СУБД для словаря

Прежде чем углубиться в установку и работу с конкретной СУБД, обсудим, какой выбор подходит для арабо-русского словаря. Существует три популярных реляционных СУБД, доступных в Debian: SQLite, PostgreSQL и MariaDB. Каждая имеет свои сильные стороны и сценарии применения.

Критерии выбора

Для словаря ключевые критерии таковы. Поддержка Unicode — критическая, ведь и арабский, и русский используют не-ASCII символы. Простота установки важна для новичка. Производительность для словаря на 10-100 тысяч слов не критична: любая из трёх СУБД справится мгновенно. Масштабируемость: если вы планируете веб-интерфейс или многопользовательский доступ — нужна клиент-серверная СУБД.

Когда выбрать SQLite

SQLite — встроенная СУБД: нет сервера, нет сетевого доступа, нет пользователя. Вся база лежит в одном файле, который можно скопировать на флешку, отправить по почте, положить в Git. Это идеальный выбор для личного словаря,desktop-приложений, прототипов, тестов. Если ваш словарь будут использовать только вы с одного компьютера — SQLite лучший выбор. Он быстр, надёжен, не требует обслуживания.

Ограничения: один писатель в любой момент времени (другие читатели могут работать параллельно), нет сетевого доступа, нет аутентификации. Для веб-приложения с тысячами пользователей SQLite не подойдёт.

Когда выбрать PostgreSQL

PostgreSQL — мощная объектно-реляционная СУБД с акцентом на соответствие стандартам и расширяемость. Поддерживает сложные типы данных, JSON, геоданные (через PostGIS), мощный полнотекстовый поиск. Идеальный выбор для production-систем, где важна надёжность, целостность данных и богатые возможности SQL.

Для словаря PostgreSQL даёт две важные вещи. Во-первых, корректный collation для арабского — сортировка по правилам арабского алфавита, а не по кодам Unicode. Во-вторых, мощный полнотекстовый поиск с морфологией (хотя для арабского нужна дополнительная конфигурация). Если вы планируете веб-версию словаря или API — PostgreSQL оправдан.

Когда выбрать MariaDB

MariaDB — форк MySQL, поддерживаемый оригинальными авторами. Популярна в веб-разработке, особенно в связке с PHP (WordPress, Joomla). Простая в установке и освоении, имеет хорошую производительность для типичных веб-запросов. Если вы планируете веб-словарь на PHP или уже знакомы с MySQL — MariaDB будет логичным выбором.

Для арабского важно использовать кодировку utf8mb4, а не utf8 (которая в MySQL/MariaDB поддерживает только BMP до 3 байт). Арабские символы помещаются в BMP, так что utf8 технически работает, но utf8mb4 — более правильный и будущий-устойчивый выбор.

Рекомендация для нашего проекта

Рекомендация

Для личного арабо-русского словаря используйте SQLite. Это самый простой старт: одна команда установки, один файл БД, легко бэкапить. Когда словарь вырастет или понадобится веб-доступ — мигрируйте на PostgreSQL. MariaDB рассматривайте, если уже есть опыт с MySQL или планируется PHP-стек.

В этой книге мы рассмотрим все три СУБД, чтобы вы могли выбрать подходящую. Главы 12-14 показывают установку и базовые операции, глава 15 — единую SQL-схему, работающую во всех трёх. В главах 16-19 Bash-скрипты написаны так, чтобы легко переключаться между СУБД через переменную окружения.

SQLite: установка и основы

SQLite — самая простая в установке и использовании СУБД из нашего обзора. Это встраиваемая БД: вместо сервера с сетевым доступом — библиотека, которая работает с файлом напрямую. Идеальный выбор для личного словаря, прототипов, тестов и любых приложений, где не нужен параллельный доступ нескольких процессов на запись.

Unicode и арабский в SQLite

SQLite хранит строки в UTF-8 без настройки кодировки — это упрощает жизнь. Однако сортировка по умолчанию идёт по бинарным кодам символов, а не по правилам языка. Для корректной сортировки арабских и русских слов используйте COLLATE с ICU-сопоставлением (если SQLite собран с ICU, что в Debian по умолчанию).

Сортировка по локалиsql
-- По умолчанию: бинарная сортировка
SELECT arabic FROM words ORDER BY arabic;

-- С ICU collation (если доступен)
SELECT arabic FROM words ORDER BY arabic COLLATE NOCASE;

-- Для русского — тоже NOCASE подойдёт для регистра
SELECT russian FROM words ORDER BY russian COLLATE NOCASE;

Если ICU недоступен, сортировка по правилам языка делается на стороне приложения (например, через sort с установленной локалью в Bash).

PostgreSQL: установка и основы

PostgreSQL — мощная объектно-реляционная СУБД с акцентом на соответствие стандартам SQL, расширяемость и надёжность. В отличие от SQLite, PostgreSQL работает как сервер: имеет процесс-демон, слушает сетевой порт (5432 по умолчанию), поддерживает аутентификацию и многопользовательский доступ. Для production-систем и веб-приложений PostgreSQL — один из лучших выборов.

Установка

user@debian:~$ sudo apt install -y postgresql postgresql-client
user@debian:~$ psql --version
psql (PostgreSQL) 15.5 (Debian 15.5-0+deb12u1)

user@debian:~$ sudo systemctl status postgresql
● postgresql.service - PostgreSQL RDBMS
     Loaded: loaded (...; enabled; preset: enabled)
     Active: active (exited) since ...

После установки PostgreSQL создаёт системного пользователя postgres, который является суперпользователем БД. В Debian аутентификация по умолчанию — peer: локальный пользователь postgres может войти в БД без пароля, другие пользователи должны соответствовать системным именам.

Создание пользователя и базы

Чтобы работать с PostgreSQL от своего обычного пользователя, создайте для него роль и базу:

user@debian:~$ sudo -u postgres psql
psql (15.5)
Введите "help", чтобы получить справку.

postgres=#

postgres=# CREATE USER user WITH PASSWORD 'secret';
CREATE ROLE
postgres=# CREATE DATABASE dict_ar_ru OWNER user ENCODING 'UTF8' LC_COLLATE 'ru_RU.UTF-8' LC_CTYPE 'ru_RU.UTF-8' TEMPLATE template0;
CREATE DATABASE
postgres=# \q
user@debian:~$

Здесь мы создали пользователя user (замените на ваш логин) с паролем secret (придумайте свой), и базу dict_ar_ru с UTF-8 и русской локалью. Если локали ru_RU.UTF-8 нет, сначала сгенерируйте её через sudo dpkg-reconfigure locales.

Подключение и psql

Клиент psql — основной инструмент работы с PostgreSQL. Полезные ключи: -h (хост, по умолчанию локальный Unix-сокет), -U (пользователь), -d (база), -c (выполнить команду), -f (выполнить файл).

user@debian:~$ psql -d dict_ar_ru
psql (15.5)

Глава 15 · Схема

SQL-схема словаря

Схема базы данных — это структура таблиц, индексов и связей между ними. Хорошая схема — основа производительного и поддерживаемого приложения. Для арабо-русского словаря мы спроектируем схему, которая поддерживает не только пары слов, но и категории, примеры употребления, транскрипцию и историю изменений.

Анализ предметной области

Что мы хотим хранить? Каждая запись — это арабское слово, его русский перевод, транскрипция латиницей (для тех, кто не читает по-арабски), часть речи (существительное, глагол, прилагательное и т. д.). Хочется хранить примеры употребления — фразы на арабском с переводом, чтобы показать слово в контексте. Полезна категоризация: еда, путешествия, бизнес, религия. И timestamp — когда добавлено, когда изменено.

Связи между сущностями: одно слово может иметь несколько примеров (one-to-many). Одно слово может принадлежать нескольким категориям, и в одной категории много слов (many-to-many). Это требует таблицы-связки word_categories.

Диаграмма схемы

words (1) ──────── (N) examples
   │
   │
   └─── (N) word_categories (N) ──── categories (1)

Универсальная схема

Ниже SQL-схема, работающая во всех трёх СУБД с минимальными изменениями. Основные отличия: тип автоинкрементного PK (SERIAL в PostgreSQL, AUTO_INCREMENT в MariaDB, AUTOINCREMENT в SQLite) и функция текущего времени (NOW(), CURRENT_TIMESTAMP, datetime('now')).

schema.sql (SQLite-версия)sql
-- Главная таблица: слова
CREATE TABLE IF NOT EXISTS words (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    arabic TEXT NOT NULL,
    russian TEXT NOT NULL,
    transcription TEXT,
    part_of_speech TEXT CHECK (
        part_of_speech IN (
            'существительное', 'глагол', 'прилагательное',
            'наречие', 'местоимение', 'предлог',
            'союз', 'частица', 'междометие'
        )
    ),
    notes TEXT,
    created_at TEXT DEFAULT (datetime('now')),
    updated_at TEXT DEFAULT (datetime('now'))
);

-- Категории (еда, путешествия, и т.д.)
CREATE TABLE IF NOT EXISTS categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    description TEXT
);

-- Примеры употребления
CREATE TABLE IF NOT EXISTS examples (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    word_id INTEGER NOT NULL,
    arabic_text TEXT NOT NULL,
    russian_text TEXT NOT NULL,
    FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE CASCADE
);

-- Связь many-to-many: слово ↔ категория
CREATE TABLE IF NOT EXISTS word_categories (
    word_id INTEGER NOT NULL,
    category_id INTEGER NOT NULL,
    PRIMARY KEY (word_id, category_id),
    FOREIGN KEY (word_id) REFERENCES words(id) ON DELETE CASCADE,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE
);

-- Индексы для быстрого поиска
CREATE INDEX IF NOT EXISTS idx_words_arabic ON words(arabic);
CREATE INDEX IF NOT EXISTS idx_words_russian ON words(russian);
CREATE INDEX IF NOT EXISTS idx_words_pos ON words(part_of_speech);
CREATE INDEX IF NOT EXISTS idx_examples_word ON examples(word_id);

-- Триггер: обновлять updated_at при изменении
CREATE TRIGGER IF NOT EXISTS trg_words_updated
AFTER UPDATE ON words
FOR EACH ROW
BEGIN
    UPDATE words SET updated_at = datetime('now') WHERE id = OLD.id;
END;

Абстракция БД: db.sh

Создадим слой абстракции, который скрывает различия между СУБД. Каждая функция проверяет $DB_ENGINE и вызывает соответствующую реализацию.

scripts/lib/db.sh — слой абстракцииbash
#!/bin/bash
# lib/db.sh — абстракция над СУБД

db_query() {
    # $1 — SQL, опционально $2 — формат вывода
    local sql="$1"
    case "$DB_ENGINE" in
        sqlite)
            sqlite3 "$SQLITE_DB" "$sql"
            ;;
        postgresql)
            psql -t -U "$PG_USER" -d "$PG_DB" -c "$sql"
            ;;
        mariadb)
            mariadb "$MY_DB" -N -e "$sql"
            ;;
        *)
            log ERROR "Неизвестная СУБД: $DB_ENGINE"
            return 1
            ;;
    esac
}

db_query_pretty() {
    # Вывод в виде красивой таблицы
    local sql="$1"
    case "$DB_ENGINE" in
        sqlite)     sqlite3 -header -column "$SQLITE_DB" "$sql" ;;
        postgresql) psql -U "$PG_USER" -d "$PG_DB" -c "$sql" ;;
        mariadb)    mariadb "$MY_DB" -t -e "$sql" ;;
    esac
}

db_escape() {
    # Экранирование одинарных кавычек для SQL
    local s="$1"
    echo "${s//\'/\'\'}"
}

#!/bin/bash
# lib/dict.sh — high-level операции

dict_add() {
    local ar="$(db_escape "$1")"
    local ru="$(db_escape "$2")"
    local tr="$(db_escape "$3")"
    local pos="$(db_escape "$4")"

    [[ -z "$ar" || -z "$ru" ]] && {
        log ERROR "Требуются арабское и русское слова"
        return 1
    }

    db_query "INSERT INTO words (arabic, russian, transcription, part_of_speech)
                 VALUES ('$ar', '$ru', '$tr', '$pos');" \
        && log INFO "Добавлено: $ar → $ru"
}

dict_search() {
    local q="$(db_escape "$1")"
    db_query_pretty "SELECT id, arabic, russian, transcription, part_of_speech
        FROM words
        WHERE arabic LIKE '%$q%' OR russian LIKE '%$q%' OR transcription LIKE '%$q%'
        ORDER BY arabic;"
}

dict_list() {
    db_query_pretty "SELECT id, arabic, russian, transcription
        FROM words ORDER BY arabic;"
}

dict_count() {
    db_query "SELECT COUNT(*) FROM words;"
}

dict_delete() {
    local id="$1"
    db_query "DELETE FROM words WHERE id = $id;" \
        && log INFO "Удалена запись #$id"
}

dict_update() {
    local id="$1"
    local field="$(db_escape "$2")"
    local value="$(db_escape "$3")"

    # Белый список полей для защиты от SQL-инъекций
    case "$field" in
        arabic|russian|transcription|part_of_speech|notes) ;;
        *) log ERROR "Недопустимое поле: $field"; return 1 ;;
    esac

    db_query "UPDATE words SET $field = '$value' WHERE id = $id;" \
        && log INFO "Обновлено: #$id.$field = $value"
}

Глава 17 · Импорт CSV

Импорт данных из CSV

Вводить слова по одному через форму — медленно. Обычно словарь импортируют из готового CSV-файла: либо собственного, либо скачанного из открытых источников. В этой главе разберём, как подготовить CSV и импортировать его в каждую из трёх СУБД.

Формат CSV

CSV (Comma-Separated Values) — простейший формат табличных данных. Каждая строка — запись, поля разделены запятыми, первая строка обычно — заголовок. Для нашего словаря:

data/words.csvcsv
arabic,russian,transcription,part_of_speech
كتاب,книга,kitab,существительное
باب,дверь,bab,существительное
ماء,вода,maa,существительное
سلام,мир,salaam,существительное
يأكل,есть,yakul,глагол
كبير,большой,kabir,прилагательное
جميل,красивый,jamil,прилагательное
أنا,я,ana,местоимение
أين,где,ayn,вопросительное слово
شكرا,спасибо,shukran,междометие

Если в данных есть запятые внутри значений (например, «спасибо, благодарю»), это поле заключается в двойные кавычки: "спасибо, благодарю". Если в значении есть кавычки — они удваиваются: "он сказал ""привет""".

Файл должен быть в UTF-8 без BOM. Проверить:

user@debian:~/dict-ar-ru$ file data/words.csv
data/words.csv: Unicode text, UTF-8 text

user@debian:~/dict-ar-ru$ head -3 data/words.csv | hexdump -C | head -5
00000000  61 72 61 62 69 63 2c 72  75 73 73 69 61 6e 2c 74  |arabic,russian,t|
00000010  72 61 6e 73 63 72 69 70  74 69 6f 6e 2c 70 61 72  |ranscription,par|
... (нет EF BB BF в начале — значит без BOM)

Импорт в SQLite

SQLite имеет встроенную команду .import для CSV. Важно настроить режим CSV, чтобы корректно обрабатывались кавычки.

Импорт в SQLitebash
# Способ 1: через интерактивный режим
sqlite3 data/dict.db
sqlite> .mode csv
sqlite> .import --skip 1 data/words.csv words

# Способ 2: через here-doc
sqlite3 data/dict.db <<SQL
.mode csv
.import --skip 1 data/words.csv words
SQL

# Способ 3: Bash-скрипт с построчной обработкой
# (если нужен контроль или трансформация данных)
while IFS=, read -r ar ru tr pos; do
    [[ "$ar" == "arabic" ]] && continue   # пропустить заголовок
    sqlite3 data/dict.db \
        "INSERT INTO words (arabic, russian, transcription, part_of_speech) VALUES ('$ar', '$ru', '$tr', '$pos');"
done < data/words.csv

Флаг --skip 1 пропускает заголовок. В старых версиях SQLite (до 3.23) этого флага нет — заголовок приходится пропускать вручную через tail -n +2.

Импорт в PostgreSQL

PostgreSQL предлагает команду COPY — одну из самых быстрых для массовой загрузки. Есть серверная COPY (файл должен быть доступен серверу) и клиентская \copy (файл читается клиентом, доступен локально).

Импорт в PostgreSQLbash
# Способ 1: \copy из psql (рекомендуемый для локальных файлов)
psql -U "$USER" -d dict_ar_ru -c \
    "\copy words(arabic, russian, transcription, part_of_speech) FROM 'data/words.csv' WITH (FORMAT csv, HEADER true);"

# Способ 2: COPY FROM STDIN через here-doc
psql -U "$USER" -d dict_ar_ru <<SQL
\copy words(arabic, russian, transcription, part_of_speech) FROM 'data/words.csv' WITH (FORMAT csv, HEADER true)
SQL

# Способ 3: серверный COPY (требует прав суперпользователя)
psql -U postgres -d dict_ar_ru -c \
    "COPY words(arabic, russian, transcription, part_of_speech) FROM '/abs/path/words.csv' WITH (FORMAT csv, HEADER true);"

Параметр FORMAT csv включает правильную обработку кавычек. HEADER true пропускает первую строку. Для путей обязательно указывать абсолютный путь при серверном COPY.

Импорт в MariaDB

MariaDB использует LOAD DATA INFILE. По умолчанию файл должен лежать в каталоге, указанном в переменной secure_file_priv (проверить: SHOW VARIABLES LIKE 'secure_file_priv';). Если значение пустое — можно грузить откуда угодно, если NULL — загрузка запрещена.

Импорт в MariaDBbash
# Способ 1: LOAD DATA LOCAL INFILE (файл на клиенте, не требует прав сервера)
mariadb --local-infile=1 dict_ar_ru -e "
LOAD DATA LOCAL INFILE 'data/words.csv'
INTO TABLE words
CHARACTER SET utf8mb4
FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '\"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS
(arabic, russian, transcription, part_of_speech);
"

# Способ 2: если secure_file_priv пустой
mariadb dict_ar_ru -e "
LOAD DATA INFILE '/abs/path/words.csv'
INTO TABLE words
CHARACTER SET utf8mb4
FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '\"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS
(arabic, russian, transcription, part_of_speech);
"

Параметр CHARACTER SET utf8mb4 критичен — без него MariaDB может неверно интерпретировать байты. OPTIONALLY ENCLOSED BY '\"' указывает, что поля могут быть в кавычках. IGNORE 1 ROWS пропускает заголовок.

Глава 18 · Ошибки

Обработка ошибок и безопасность

Любойproduction-скрипт должен корректно обрабатывать ошибки. По умолчанию Bash продолжает выполнение после сбоя команды, что часто приводит к трудно диагностируемым багам: скрипт «успешно» завершается, но данные повреждены, файлы частично обновлены, база в несогласованном состоянии. В этой главе разберём практики, которые делают Bash-скрипты надёжными.

Коды возврата и $?

Каждая команда возвращает числовой код от 0 до 255: 0 означает успех, ненулевое — ошибку. Код последней команды сохраняется в переменной $?. Проверяйте его после критичных операций.

Проверка кода возвратаbash
sqlite3 "$SQLITE_DB" "INSERT INTO words VALUES (...);"
if [[ $? -ne 0 ]]; then
    log ERROR "Не удалось вставить запись"
    exit 1
fi

# Или коротко с помощью ||
sqlite3 "$SQLITE_DB" "INSERT ..." || {
    log ERROR "Ошибка вставки"
    exit 1
}

set -e, set -u, set -o pipefail

Три опции, которые должен включать каждый production-скрипт:

  • set -e — немедленно выйти, если любая команда вернёт ненулевой код. Без этого скрипт продолжит работу даже после ошибки.
  • set -u — ошибка при обращении к неопределённой переменной. Ловит опечатки в именах переменных.
  • set -o pipefail — код возврата конвейера равен коду первой упавшей команды, а не последней. Без этого false | true вернёт 0 (успех).

Обычно их объединяют в одной строке в начале скрипта:

set -euo pipefailbash
#!/bin/bash
set -euo pipefail
#等同于: set -e; set -u; set -o pipefail

# Этот скрипт упадёт, если:
# - любая команда вернёт ненулевой код
# - будет обращение к неопределённой переменной
# - любая команда в конвейере упадёт

source config.sh
dict_add "$1" "$2" "$3"
echo "Успешно добавлено"

Иногда set -e слишком агрессивна: вы хотите, чтобы команда могла упасть, и вы обработаете это. В таком случае используйте || true или временно отключайте -e:

Исключения для set -ebash
# Команда может упасть — это нормально
grep "что-то" file.txt || true      # grep возвращает 1, если нет совпадений
rm -f /tmp/tempfile 2>/dev/null || true

# Временно отключить
set +e
some_dangerous_command
result=$?
set -e

if (( result != 0 )); then
    echo "Обработано"
fi

trap: очистка при выходе

Команда trap задаёт команду, которая выполнится при получении сигнала (EXIT, INT, TERM, ERR). Полезна для удаления временных файлов, закрытия соединений с БД, отката транзакций.

trap — очисткаbash
#!/bin/bash
set -euo pipefail

TMP_FILE=$(mktemp)
trap 'rm -f "$TMP_FILE"' EXIT
# При любом выходе (нормальном, по ошибке, по Ctrl+C)
# временный файл будет удалён

# Ловушка на ERR — для логирования ошибок
trap 'echo "Ошибка на строке $LINENO" >&2' ERR

# Используем временный файл
sqlite3 data/dict.db "SELECT * FROM words" > "$TMP_FILE"
wc -l "$TMP_FILE"

Специальные переменные в trap: $LINENO (номер строки), $BASH_COMMAND (команда, которая упала), $? (код возврата). Полный пример обработчика ошибок:

Полный обработчик ошибокbash
on_error() {
    local exit_code=$?
    local line=$1
    local cmd=$2
    echo "ОШИБКА: команда '$cmd' на строке $line вернула $exit_code" >&2
    exit $exit_code
}
trap 'on_error $LINENO "$BASH_COMMAND"' ERR

# Альтернатива: просто логирование
trap 'echo "Скрипт завершился с кодом $?" >> logs/dict.log' EXIT

Логирование

Каждая важная операция должна логироваться. Лог позволяет事后 понять, что произошло, и отладить проблемы. Хороший лог содержит: timestamp, уровень (INFO/WARN/ERROR), сообщение.

Функция логированияbash
log() {
    local level="$1"; shift
    local msg="$*"
    local ts=$(date +'%Y-%m-%d %H:%M:%S')
    local script=$(basename "${BASH_SOURCE[1]}")
    local line="${BASH_LINENO[0]}"

    echo "[$ts] [$level] [$script:$line] $msg" >> "$LOG_DIR/dict.log"

    case "$level" in
        ERROR) echo -e "${CLR_RED}[$level] $msg${CLR_RESET}" >&2 ;;
        WARN)  echo -e "${CLR_YELLOW}[$level] $msg${CLR_RESET}" >&2 ;;
        INFO)  [[ "${VERBOSE:-0}" == "1" ]] && echo "[$level] $msg" ;;
    esac
}

# Использование
log INFO "Запуск скрипта"
log WARN "Файл пустой: $file"
log ERROR "Не удалось подключиться к БД"
VERBOSE=1 log INFO "Отладочное сообщение"

Валидация ввода

Никогда не доверяйте пользовательскому вводу. Проверяйте: что аргументы переданы, что файлы существуют, что строки соответствуют ожидаемому формату.

Валидация аргументовbash
validate_args() {
    if [[ $# -lt 2 ]]; then
        echo "Использование: $0 <arabic> <russian> [transcription]" >&2
        exit 1
    fi

    local ar="$1" ru="$2"

    # Арабское слово: только арабские буквы
    [[ "$ar" =~ ^[\u0600-\u06FF]+$ ]] || {
        echo "Ошибка: '$ar' не похоже на арабское слово" >&2
        exit 1
    }

    # Русское слово: только кириллица и дефис
    [[ "$ru" =~ ^[а-яА-ЯёЁ-]+$ ]] || {
        echo "Ошибка: '$ru' не похоже на русское слово" >&2
        exit 1
    }

    # Проверка длины
    (( ${#ar} > 100 )) && {
        echo "Ошибка: слишком длинное арабское слово" >&2
        exit 1
    }
}

validate_args "$@"

Защита от SQL-инъекций

SQL-инъекция — это атака, когда злоумышленник вставляет SQL-код в данные. Пример: пользователь вводит «книга'); DROP TABLE words;--». Если скрипт просто подставляет это в SQL, таблица будет удалена. Защита: экранирование или параметризованные запросы.

Защита от SQL-инъекцийbash
# Плохо: прямая подстановка
sqlite3 data/dict.db "SELECT * FROM words WHERE arabic = '$user_input';"
# Если $user_input = "'; DROP TABLE words; --"
# Получится: SELECT * FROM words WHERE arabic = ''; DROP TABLE words; --';

# Хорошо: экранирование одинарных кавычек
db_escape() {
    echo "${1//\'/\'\'}"   # ' → ''
}
local safe=$(db_escape "$user_input")
sqlite3 data/dict.db "SELECT * FROM words WHERE arabic = '$safe';"

# Ещё лучше: использовать .param в SQLite или $1 в PostgreSQL
# SQLite:
sqlite3 data/dict.db <<SQL
.param set :ar "$user_input"
SELECT * FROM words WHERE arabic = :ar;
SQL

# PostgreSQL:
psql -v ar="$user_input" -c "SELECT * FROM words WHERE arabic = :'ar';"

Для команды dict_update из главы 16 критично использовать белый список полей, иначе злоумышленник может передать "id = 1; DROP TABLE" как имя поля.

Безопасность файлов

Права на файлыbash
# Файлы с паролями — только владелец
chmod 600 ~/.pgpass ~/.my.cnf

# Скрипты — исполняемые
chmod 700 scripts/*.sh

# БД — владелец читает/пишет, остальные — ничего

# В скрипте проверка прав

    echo "Небезопасные права на $CONFIG_FILE. Исправьте: chmod 600 $CONFIG_FILE" >&2
    exit 1
}

# Безопасное создание временного файла
TMP=$(mktemp)              # в /tmp, случайное имя, права 600
trap 'rm -f "$TMP"' EXIT

# Не используйте: TMP=/tmp/myapp.$$  — уязвимо к race condition

scripts/backup.shbash
#!/bin/bash
set -euo pipefail
source "$(dirname "$0")/config.sh"

TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="$PROJECT_ROOT/backup"
mkdir -p "$BACKUP_DIR"

log() { echo "[$(date +'%H:%M:%S')] $*"; }

case "$DB_ENGINE" in
    sqlite)
        FILE="$BACKUP_DIR/dict_$TIMESTAMP.db"
        # Способ 1: простое копирование файла
        cp "$SQLITE_DB" "$FILE"
        # Способ 2: через .dump (SQL-текст, восстанавливается в любой SQLite)
        sqlite3 "$SQLITE_DB" .dump > "$BACKUP_DIR/dict_$TIMESTAMP.sql"
        log "Бэкап SQLite: $FILE и .sql"
        ;;
    postgresql)
        FILE="$BACKUP_DIR/dict_$TIMESTAMP.sql.gz"
        pg_dump -U "$PG_USER" -d "$PG_DB" | gzip > "$FILE"
        log "Бэкап PostgreSQL: $FILE"
        ;;
    mariadb)
        FILE="$BACKUP_DIR/dict_$TIMESTAMP.sql.gz"
        mysqldump --defaults-file="$HOME/.my.cnf" "$MY_DB" | gzip > "$FILE"
        log "Бэкап MariaDB: $FILE"
        ;;
esac

# Удаление старых бэкапов (старше 30 дней)
find "$BACKUP_DIR" -name "dict_*" -mtime +30 -delete
log "Старые бэкапы удалены"

scripts/restore.shbash
#!/bin/bash
set -euo pipefail
source "$(dirname "$0")/config.sh"

BACKUP_FILE="$1"

[[ ! -f "$BACKUP_FILE" ]] && {
    echo "Файл не найден: $BACKUP_FILE" >&2
    exit 1
}

echo "Внимание: текущие данные будут заменены. Продолжить? [y/N]"
read -r ans
[[ "$ans" =~ ^[Yy]$ ]] || exit 0

case "$DB_ENGINE" in
    sqlite)
        if [[ "$BACKUP_FILE" == *.sql ]]; then
            rm -f "$SQLITE_DB"
            sqlite3 "$SQLITE_DB" < "$BACKUP_FILE"
        else
            cp "$BACKUP_FILE" "$SQLITE_DB"
        fi
        ;;
    postgresql)
        gunzip -c "$BACKUP_FILE" | psql -U "$PG_USER" -d "$PG_DB"
        ;;
    mariadb)
        gunzip -c "$BACKUP_FILE" | mariadb "$MY_DB"
        ;;
esac

echo "Восстановлено из $BACKUP_FILE"

Cron: автоматические бэкапы

Cron — системный планировщик задач. Запускает команды по расписанию. Чтобы настроить ежедневный бэкап в 3 часа ночи, отредактируйте crontab:

user@debian:~$ crontab -e
# Открыт редактор (обычно nano). Добавьте строку:

# Ежедневный бэкап в 3:00
0 3 * * * /home/user/dict-ar-ru/scripts/backup.sh >> /home/user/dict-ar-ru/logs/cron.log 2>&1

# Еженедельный экспорт в CSV по воскресеньям в 4:00
0 4 * * 0 /home/user/dict-ar-ru/scripts/export_csv.sh >> /home/user/dict-ar-ru/logs/cron.log 2>&1

# Сохранить и выйти (в nano: Ctrl+O, Enter, Ctrl+X)

user@debian:~$ crontab -l   # проверить

Формат cron: минута час день_месяца месяц день_недели команда. Звёздочка — любое значение. */5 — каждые 5 минут. 0 3 * * * — каждый день в 3:00. 0 4 * * 0 — каждое воскресенье в 4:00.

    local actual="$3"
    if [[ "$expected" == "$actual" ]]; then

        echo "  ✓ $desc"
    else
        ((fail++))

}

test_assert "Увеличение count" "$((before + 1))" "$after"

echo
echo "=== Итог: $pass passed, $fail failed ==="
exit $((fail > 0 ? 1 : 0))

Идеи для развития проекта

Созданный нами словарь — это фундамент. Вот несколько направлений, как его можно развить.

Веб-интерфейс. Превратите словарь в веб-приложение. Простой вариант: CGI-скрипт на Bash, который через printf "Content-Type: text/html\n\n" выводит HTML. Серьёзный вариант: Flask (Python) или Express (Node.js) как фронтенд, оставляя нашу SQLite-БД как хранилище. Это откроет словарь для доступа из браузера и с телефона.

Полнотекстовый поиск. SQLite FTS5 и PostgreSQL tsvector дают мощный поиск с ранжированием по релевантности, морфологией, стоп-словами. Для арабского нужна дополнительная конфигурация (Arabic stemmer), но результат того стоит.

Мобильное приложение. React Native или Flutter позволяют переиспользовать SQLite-БД на мобильных устройствах. Словарь в кармане — отличный продукт для изучающих арабский.

Экспорт в Anki. Anki — популярная программа для интервального повторения. Экспортируйте словарь в формат Anki-карточек (TSV с разделителями), и пользователи смогут учить слова с эффективностью интервального повторения.

API. Опубликуйте REST API для доступа к словарю: GET /api/words?q=книга. Это позволит другим разработчикам создавать поверх вашего словаря свои приложения.

Нормализация арабского. Реализуйте функции нормализации: удаление огласовок, унификация алифов (آ أ إ → ا), та марбута (ة → ه), проверка хамзы. Это сделает поиск более толерантным к вариантам написания.

Импорт из внешних словарей. Существуют открытые арабо-английские словари (Wiktionary, dict.cc). Напишите парсеры, которые загружают их в вашу БД с автоматическим переводом на русский через API.

Финальный скрипт dict.sh — полный текст

Для справки — компактная версия главного скрипта со всеми подкомандами. Полная версия с библиотеками — в репозитории проекта.

scripts/dict.sh (компактная версия)bash
#!/bin/bash
set -euo pipefail

# Конфигурация
export LC_ALL=ru_RU.UTF-8
export DB_ENGINE="${DB_ENGINE:-sqlite}"
export SQLITE_DB="$HOME/dict-ar-ru/data/dict.db"
export PG_DB="dict_ar_ru" PG_USER="$USER"
export MY_DB="dict_ar_ru"

db_query() {
    case "$DB_ENGINE" in
        sqlite)     sqlite3 "$SQLITE_DB" "$1" ;;
        postgresql) psql -t -U "$PG_USER" -d "$PG_DB" -c "$1" ;;
        mariadb)    mariadb -N "$MY_DB" -e "$1" ;;
    esac
}

db_pretty() {
    case "$DB_ENGINE" in
        sqlite)     sqlite3 -header -column "$SQLITE_DB" "$1" ;;
        postgresql) psql -U "$PG_USER" -d "$PG_DB" -c "$1" ;;
        mariadb)    mariadb -t "$MY_DB" -e "$1" ;;
    esac
}

db_escape() { echo "${1//\'/\'\'}"; }

usage() {
    cat <<EOF
Использование: dict.sh <команда> [аргументы]
Команды: add search list count delete update help
СУБД: DB_ENGINE=sqlite|postgresql|mariadb (по умолчанию sqlite)
EOF
}

[[ $# -eq 0 ]] && { usage; exit 0; }

case "$1" in
    add)
        ar=$(db_escape "$2"); ru=$(db_escape "$3")
        tr=$(db_escape "${4:-}"); pos=$(db_escape "${5:-}")
        db_query "INSERT INTO words (arabic, russian, transcription, part_of_speech)
            VALUES ('$ar', '$ru', '$tr', '$pos');"
        echo "Добавлено: $2 → $3"
        ;;
    search)
        q=$(db_escape "$2")
        db_pretty "SELECT * FROM words WHERE arabic LIKE '%$q%' OR russian LIKE '%$q%';"
        ;;
    list)
        db_pretty "SELECT * FROM words ORDER BY arabic;"
        ;;
    count)
        echo "Записей: $(db_query 'SELECT COUNT(*) FROM words;')"
        ;;
    delete)
        db_query "DELETE FROM words WHERE id = $2;"
        echo "Удалено: #$2"
        ;;
    update)
        case "$3" in arabic|russian|transcription|part_of_speech|notes) ;;
            *) echo "Недопустимое поле" >&2; exit 1 ;;
        esac
        v=$(db_escape "$4")
        db_query "UPDATE words SET $3 = '$v' WHERE id = $2;"
        echo "Обновлено"
        ;;
    help|--help|-h) usage ;;
    *) echo "Неизвестная команда: $1" >&2; usage; exit 1 ;;
esac
